# CodeRelayBridge（CRB）使用指南

[English](USER_GUIDE.en.md) · [返回首页](../README.md)

本文介绍完整原生安装包的首次安装与配置，无需预先配置 Python、SSH 或手写连接文件。客户端、服务端和网页均支持中英文界面。

## 界面语言

首次启动读取系统首选界面语言：中文使用中文，其他语言使用英文；网页读取浏览器首选语言。手动选择后保存，并优先于后续系统语言变化。界面语言不按数字/日期的地区格式猜测。

- 客户端：左下角“语言”。
- 服务端：“连接与首次设置”中的语言列表。
- 网页：左下角主题旁的语言列表。

目前只提供“中文”和“English”，每个安装/浏览器分别记录选择。切换不重连、不发送桥接指令、不清空草稿，也不翻译聊天正文、问题选项、项目/文件名称、日志或终端输出。Codex 原生已有功能沿用对应术语，其余 CRB 功能独立翻译。英文界面的首次配对入口分别为 “Settings & setup”“Pair / add app”“Pair & connect”。

## 1. 先理解三种角色

| 角色 | 安装位置 | 用途 |
| --- | --- | --- |
| CRB 服务端 | 一台保持联网的 Windows、Linux 或 Mac | 提供网页、登录、设备配对与消息转发 |
| CRB 客户端 | 每台要接入的电脑 | 桥接这台电脑的桌面 AI App |
| 浏览器 | 手机、平板或电脑 | 访问服务端并操作已配对的对话 |

服务端不代替桌面 AI App，也不提供模型账号。Codex、DeepSeek Harness 及其登录/API 配置要在各客户端电脑上另行完成。Claude 原桌面 Code 会话尚未完成接入，不能当作已支持功能。

一台电脑可以同时安装服务端和客户端；只安装服务端，不会自动接入它本机的 AI App。手机只需浏览器；跨网络时还需要下面介绍的虚拟局域网 App。

## 2. 网络前提：先有可互通的局域网

请选择一种方式，不必两种 VPN 都装：

- **同一可信局域网**：服务端、客户端和浏览器设备能互相访问。连接同一路由器的访客 Wi-Fi、开启设备隔离的无线网络，不一定满足此条件。
- **不同地点/手机流量**：推荐 Tailscale；也可选 ZeroTier。先让相关设备加入同一虚拟局域网，再配置 CRB。

CRB 不自带穿透云、VPN、公共服务器或共享账号。Tailscale/ZeroTier 只解决网络可达性，不替你启动 CRB，也不替代 CRB 的网页登录与配对。[Tailscale 官方连接说明](https://tailscale.com/docs/how-to/connect-to-devices)

客户端通常主动连接服务端，不需要给每台客户端开放 SSH、模型 API 或调试端口。浏览器也连接服务端。基本部署需要服务端的 **TCP 8799** 可达；修改端口后，所有地址都要使用你设置的端口。

## 3. 下载及安装

从本项目的 [GitHub Releases](https://github.com/Gabriel0224/CodeRelayBridge/releases) 下载对应系统和角色的完整包。普通版公开发布；Cockpit 集成版不在这个公开仓库提供。不要把客户端当服务端用，或把 Windows 包放到 Linux 使用。

- **Windows x64**：把 ZIP 全部解压到固定目录，进入 `RelayServer` 或 `RelayClient` 目录，运行对应的 `.exe`。保留 `_internal` 等同级文件，不能只复制 EXE。不要直接在压缩包预览中运行。
- **Ubuntu / Mint（Linux x64）**：完整解压 TAR.GZ，进入应用目录运行 `RelayServer` / `RelayClient`。在有图形桌面的用户会话中启动；使用文件管理器或终端都可以。解压后的同级库和资源目录不能删除。
- **macOS Apple Silicon**：打开 DMG，将 `Relay Server.app` / `Relay Client.app` 拷贝到应用目录后运行。当前安装包要求 **macOS 27 或以上**，不支持 Intel Mac；具体要求以所选 Release 为准。

完整包附带 Python、Qt 及打包运行依赖，但不能代替操作系统和图形驱动。Linux 若缺系统图形库，可使用“网络与依赖”检测并按提示授权修复；不能承诺任意旧系统都能运行。

来源不明、校验不符或被安全软件告警时，先核对 Release 与校验文件，不要关闭防护或给整个网站加白名单。若系统拦截未签名程序，只在确认来源后按系统的单应用批准流程处理。不要全局关闭 Gatekeeper。

## 4. 配置第一台服务端

### 4.1 获取地址

在服务端电脑的网络设置里查看当前网卡的 **IPv4 地址**。Windows 也可运行 `ipconfig`；Linux 可运行 `ip -4 addr`；Mac 可在系统设置的网络详情中查看。

本文写作 `SERVER_IP` 的位置必须替换成你自己服务端的实际地址；不要照抄占位符。使用 Tailscale 或 ZeroTier 时，改用该服务端的虚拟网卡 IPv4，见第 7、8 节。

### 4.2 从 UI 创建配置

1. 打开 `RelayServer`，进入 **“连接与首次设置”**。
2. **监听 IP**：填服务端当前的局域网 IPv4；使用虚拟局域网时填它的虚拟 IPv4。先连接网络，再启动服务。
3. **监听端口**：通常保留 `8799`。
4. **网页访问地址**：填写 `http://SERVER_IP:8799`，其中 `SERVER_IP` 必须已替换。只在可信局域网或加密虚拟局域网内使用此 HTTP 地址。
5. **网页登录账号/密码**：由你创建；密码至少 8 位，建议使用独立的随机长密码。新安装不预设账号、密码或服务器地址。
6. 点击 **“创建服务器配置”**。
7. 保留 **“启动时自动配置系统端口与依赖”**，然后点击 **“启动服务”**。若弹出本机系统授权，核对仅为 CRB 的端口/依赖后授权。
8. 在服务端本机访问上面填写的地址，确认能登录。
9. **再从另一台电脑或手机访问同一地址并登录**。这一步成功才证明局域网访问成立。

`127.0.0.1` 仅指打开网页那台设备本身，只监听这个地址时其他设备进不来。`0.0.0.0` 是“监听所有 IPv4 网卡”，不是浏览器访问地址；它可能扩大暴露范围，新手建议先绑定要使用的单个网卡 IP。

自动修复只配置本程序所需规则，不能绕过公司策略、第三方防火墙、Wi-Fi 隔离、路由器或云安全组。IP 变化或 VPN 断开时，绑定旧 IP 的服务可能无法启动；使用路由器 DHCP 地址保留，或重新核对监听设置。不要为排障开放任意来源/所有端口。

## 5. 在每台电脑上通过 UI 接入

1. 先在这台电脑安装并登录对应的 Codex / DeepSeek Harness 桌面 App。原 App 的版本和平台会影响桥接能力。
2. 安装并打开 `RelayClient` 普通版。
3. 进入 **“配对 / 添加应用”**。
4. **电脑名称**：输入容易区分的名称，如“工作电脑”；这个名称显示在网页里。
5. **网页面板地址**：填写第 4 节验证成功的服务端地址。
6. **网页登录账号/密码**：填你刚在服务端创建的那一组。
7. 勾选已安装、希望接入的应用，可同时选择 Codex 和 DeepSeek。
8. 一般不要改 **“高级：后台服务器地址”**，它应与网页面板地址相同。仅已有独立反向代理部署才可能需要不同值。
9. 点击 **“检查服务器”**，通过后点击 **“配对并接入”**，等待概览的服务器/桌面 App 状态。
10. 若显示服务器已连接但桌面 App 未连接，启动相应原 App，查看客户端诊断；不要反复配对。可用 **“启动 App”** 和 **“重新连接”** 操作桥接。

**这不是 Windows、微软账户、SSH 或系统密码，也不是 DeepSeek API Key。** 网页登录密码仅在配对时使用，客户端之后使用服务器签发的设备连接凭证。不要把设备凭证或配置文件发到 Issue。

配对代表授权网页访问本机的对话、文件和终端；只配对你自己或你信任的服务端。某些原 App 操作可能需要它处于已登录的图形会话。客户端不会把一个未安装的原 App 自动变出来。

## 6. 浏览器、关闭和解除配对

在手机/电脑打开服务端 URL，输入同一网页登录账号和密码，选择应用、电脑、项目与对话。工作区用于汇集不同来源的对话，终端和文件操作发生在所选目标电脑，而不是手机本地。

- 客户端的 **“关闭并断开”** 或退出操作会停止它管理的桥接并断开接入；原 AI App 和历史文件不删除。
- 勾选 **“关闭窗口时最小化到托盘（保持接入）”** 时，关窗口仍保持接入；彻底退出使用“关闭并断开”。没有托盘时不能依靠隐藏窗口维持接入。
- 暂停单个桥接，不等于关闭原 App，也不等于撤销该电脑授权。
- 在 **配对管理** 里解除对应应用的配对，会请求撤销服务器授权并停止本机桥接，不需要再输入网页登录密码。
- **“仅断开本机”** 是服务器不可达时的应急选择，未撤销服务器授权；恢复网络后需补撤销。
- 服务端的“停止服务”/“重启服务”会断开网页及面板终端，但不停止原 AI App 的模型任务。管理 UI 与后台服务的退出规则不同，停止服务应使用明确的“停止服务”。

## 7. 推荐：通过 Tailscale 跨网络

Tailscale 的“tailnet”可理解为你的私有虚拟网络。最简单的方案不需要路由器端口映射、出口节点、子网路由或 Funnel。[官方快速开始](https://tailscale.com/docs/how-to/quickstart)

1. 从 [Tailscale 官方下载页](https://tailscale.com/download) 安装对应系统的 App。服务端电脑、每台异地客户端电脑、用流量访问的手机/平板都要安装。
2. 在各设备登录并加入 **同一个 tailnet**。个人设备可使用同一身份登录；邀请其他用户时确认他们加入的是你的网络，而不是新建的另一张网络。
3. 在 Tailscale 管理界面核对设备已连接、所需设备审批已通过。自定义访问策略必须允许客户端/浏览器访问 CRB 服务端的 TCP 8799。
4. 从设备列表记录 **服务端** 的 Tailscale IPv4。`100.x` 形式地址不能随便编；它不是互联网任何人都能访问的公网地址。
5. 新服务端的监听 IP 使用该 IPv4，网页访问地址使用 `http://SERVER_TAILSCALE_IP:8799`；替换占位符后按第 4 节创建和启动。已有服务修改监听方式时，先备份配置并安排短暂停机，不要重建覆盖已有配对。
6. 所有客户端填写同一个服务端虚拟地址进行配对；浏览器也打开该地址。
7. 手机离开 Wi-Fi，切换到移动流量，**保持 Tailscale 已连接**后测试网页登录和目标对话。

没有配置子网路由或其他明确方案的设备，单靠知道这个地址不能访问。只在服务端装 Tailscale，不会让普通手机浏览器自动获得连接能力。设备能 ping 通也不代表服务已监听或 TCP 端口已放行。[官方连接与服务要求](https://tailscale.com/docs/how-to/connect-to-devices)

MagicDNS 名称可以用于网页地址，但如果使用 HTTP 名称地址配对被拒绝，请按本指南使用实际的 Tailscale IPv4，或先配置受信任的 HTTPS；不要关闭证书校验。常规虚拟局域网方案不需要开放公网或启用 Funnel。

### 7.1 同时使用 Tailscale 与 v2rayN

以下配置建议适用于通过 **Tailscale 私有地址**访问 CRB 的桌面电脑，不是所有代理环境的通用模板。先备份 v2rayN 配置；菜单名称与进程匹配能力取决于版本和实际核心。Tailscale 官方说明两种 VPN 可能因路由、防火墙或地址冲突而不能直接共存。[官方兼容性说明](https://tailscale.com/docs/reference/faq/other-vpns)

#### 仅使用系统代理，未开启 TUN

在 v2rayN **“设置 → 参数设置 → 代理配置设置 → 例外”**中，保留原有条目，追加 CRB 服务端**实际的 Tailscale IPv4**；使用 MagicDNS 时，再追加实际完整主机名。多个条目按该输入框要求用逗号隔开，保留 `localhost`、`127.0.0.1` 等本机例外。此处是主机名／地址例外，**不要把下面的 CIDR 网段直接粘贴进来**；应用自己的代理设置也需单独核对。[v2rayN 系统代理说明](https://github.com/2dust/v2rayN/wiki/Description-of-system-proxy-routing)

#### 开启 TUN 时：网段和进程是两件事

1. 在 **“TUN 模式设置 → 路由排除地址”**中，保留已有内容并追加 `100.64.0.0/10,fd7a:115c:a1e0::/48`，使私有 IPv4／IPv6 目标不被 TUN 自动路由接管。使用 Tailscale 子网路由时，还需排除实际发布的目标子网；不要盲目排除所有私网，也不要将所有 `100.*` 地址都当作 Tailscale。
2. 核心路由规则中，把需要经过核心的上述 IP 网段设为 **`direct`（直连）**，放在兜底代理规则之前并启用对应规则集。**核心的 direct 出站不等于操作系统的 TUN 路由排除**，不能用其中一个替代另一个；仅“绕过局域网／大陆”也不保证覆盖 Tailscale。
3. 如果 TUN 仍接管 Tailscale 自身的联网流量，在 **“路由设置 → 规则详情”**中新建一条规则：**进程名 `tailscaled.exe`，出站 `direct`**，并移到兜底规则之前。这是 Windows 真正处理网络的后台服务；`tailscale.exe` 是命令行，`tailscale-ipn.exe` 是界面，不能只加后二者。若登录／界面流量也需绕过，可按实际进程另加规则。进程与 IP 分成不同规则，保存后重载 v2rayN 核心，用日志确认命中；不能假定所有核心都支持同样的进程识别。

进程规则保护的是 Tailscale 对公网节点／中继等的连接，网段排除保护的是电脑到 tailnet 的连接。Linux 后台通常是 `tailscaled`；macOS GUI 版使用网络扩展，不能照抄 Windows 进程名。也不要将 `RelayClient.exe`、`RelayServer.exe`、整个浏览器或 Codex 一律设为直连，这会同时影响它们正常的公网访问。[Tailscale 后台进程说明](https://tailscale.com/docs/reference/tailscaled) · [v2rayN 输入框与规则顺序](https://github.com/2dust/v2rayN/wiki/Description-of-some-ui) · [自定义路由格式](https://github.com/2dust/v2rayN/wiki/Description-of-custom-routing-rules)

#### DNS、出口节点与手机

- IP 地址能访问、MagicDNS 名称不能访问时，检查该私有名称是否仍由系统／Tailscale 解析，而不是被代理远端 DNS 或 FakeIP 接管。单加域名 direct 规则不保证 DNS 已正确分流；先用实际 Tailscale IP 区分路由与解析问题。[MagicDNS](https://tailscale.com/docs/features/magicdns)
- 此方案不要同时启用 Tailscale **出口节点（Exit Node）**来接管默认网络；出口节点与另一套全隧道的组合需要独立设计，不能套用这些步骤。[共存限制](https://tailscale.com/docs/reference/faq/other-vpns)
- iPhone／iPad／Android 的常规 VPN 模式通常不能同时运行两个 VPN。切到另一代理 VPN 后，Tailscale 可能断开；桌面上的进程规则不能解决这个限制。区分私有 tailnet 访问与单独配置的公网 HTTPS 入口，不要为此关闭防火墙或证书校验。

#### 验证是否真正恢复

将下面的占位符替换为自己的服务端 Tailscale IP。先保持 Tailscale 在线、关闭 v2rayN TUN 测一遍，再开启 TUN 重复相同检查：

```powershell
tailscale status
tailscale ping SERVER_TAILSCALE_IP
Test-NetConnection SERVER_TAILSCALE_IP -Port 8799
curl.exe --noproxy "*" --max-time 10 http://SERVER_TAILSCALE_IP:8799/
```

`curl --noproxy` 只排除该请求的 HTTP 代理，**不会绕过 TUN**。以真实 TCP 端口、网页登录和 CRB 桥接恢复为准；TUN 的 ICMP 应答可能不是远端主机的真实响应，不能只凭普通 ping 宣称成功。HTTP 401／登录重定向能证明服务可达，但不代表已登录；HTTPS 仍需有效证书，不使用 `-k`。[v2rayN TUN／ICMP 说明](https://github.com/2dust/v2rayN/wiki/Description-of-some-ui)

## 8. 替代方案：通过 ZeroTier 跨网络

ZeroTier 的 Network ID 是加入网络的标识，**不是 CRB 网页地址，也不是登录密码**。使用私有网络并逐台授权。[官方创建网络指南](https://docs.zerotier.com/start/)

1. 注册并登录 [ZeroTier Central](https://central.zerotier.com/)，创建私有网络，记录 16 位 Network ID。
2. 从 [ZeroTier 官方网站](https://www.zerotier.com/download/) 安装服务端、客户端电脑及手机/平板的对应 App。
3. 在各设备的 App 里选择加入网络，输入同一个 Network ID。
4. 回到 Central 的成员设备列表，核对 Node ID 与你自己的设备一致，再逐台 **Authorize（授权）**。不要授权不认识的节点。
5. 确认服务端得到 Managed IPv4，客户端/手机也得到同一网络的地址。保持 Managed IP/Routes 功能开启；虚拟网段不要与现有物理局域网重叠。
6. 新 CRB 服务端监听该 Managed IPv4，网页访问地址填 `http://SERVER_ZEROTIER_IP:8799`；替换占位符并按第 4 节启动。客户端按第 5 节配对到同一地址。
7. 检查操作系统防火墙和 ZeroTier 网络规则允许到服务端 TCP 8799，再从另一设备验证网页。
8. 手机切换流量，保持 ZeroTier VPN 已连接再验证。

成员未授权、无 Managed IPv4、错误网络 ID 或规则阻止通信时，CRB 无法自行修复这些网络设置。[官方网络与成员授权说明](https://docs.zerotier.com/networks/)

## 9. 更新、备份与常见故障

### 更新

在客户端或服务端 UI 点击 **“检查 CRB 更新”**，确认对应系统/角色/版本类型，再确认安装。更新器验证签名清单、包大小与 SHA-256；更新会短暂断开 Relay 与面板终端，不应停止原模型 App 的任务。

没有更新按钮的旧程序需首次手动换完整包。配置存放在用户数据目录，不要通过重新配对或删除配置来“升级”。集成版更新需要私有仓库读取权限，普通版更新不需要 GitHub 授权。

### 备份

备份服务端的用户数据/配对配置和客户端的连接配置；这些包含敏感信息，放在你的加密存储里。不要提交到 Git。网页数据和原 App 的聊天数据不是同一份，卸载原 App 前另行备份。

### 排障顺序

| 现象 | 先检查 |
| --- | --- |
| 本机能开，另一设备不能开 | 是否只监听 `127.0.0.1`；IP、端口、防火墙、访客 Wi-Fi 隔离 |
| 异地或手机流量进不来 | 相关设备是否加入同一 Tailscale/ZeroTier 网络且在线；成员授权与访问规则 |
| 配对 401 / 登录失败 | 用的是你自己服务端的网页登录账号/密码，不是 SSH 密码；地址前是否还有另一层登录 |
| HTTPS 报错 | 系统时间、受信任证书与域名；不要跳过证书验证 |
| 电脑在线但对话打不开 | 原桌面 App 是否安装、登录并运行；桥接状态/诊断；版本是否支持 |
| Linux UI 启动失败 | 有无图形会话；完整解压情况；缺失的系统图形库与“网络与依赖”检测 |
| 退出客户端后离线 | 这是正常行为；需要继续接入时开启保留到托盘并保持电脑唤醒 |

Windows 可用 `Test-NetConnection SERVER_IP -Port 8799` 测 TCP（先替换占位符）。其他系统用浏览器或 `curl -I http://SERVER_IP:8799/` 验证服务是否回应。HTTP 401/重定向到登录页通常证明服务可达，不能据此认定账号已验证。报告问题前遮掉令牌、账号、真实对话和个人路径。

## 10. 如果确实要公开互联网访问

这是额外的部署，不是默认局域网方案。应单独配置受信任 HTTPS、登录、访问限制、反向代理和必要的云安全组；Tailscale Funnel 等公开发布功能也需要明确评估权限和暴露范围。VPN 本身不等于公开网站。

CRB 具有文件读写、终端执行和目标应用管理能力，不能以“只有一个登录页”为由随意暴露，也不要直接把原模型 API、SSH 或本地调试端口映射到公网。
